# AlphaGRID Development Intelligence — Platform

A React + TypeScript development-intelligence platform for Sri Lankan parcels: it converts planning
regulations, parcel geometry and program intent into a cited, explainable development-capacity assessment,
with an animated, orbit-controllable 3D massing model.

This is the full platform, not a single-file demo: a marketing site, a routed application shell with sidebar
navigation, three saved-parcel workspaces, Developer / Investor / Professional modes, and a validated
regulation engine driving every number on screen.

## Quick start

```bash
npm install
npm run dev        # http://localhost:5173
```

```bash
npm run build       # production build -> dist/
npm run preview     # serve the production build locally
```

```bash
npm run build:demo  # single self-contained index.html -> dist-demo/
                     # (everything inlined — useful for sharing a live demo
                     # without deploying; not meant for production hosting)
```

## The regulation engine

`src/lib/engine.core.js` is the deterministic rule engine — the single source of truth for every FAR,
setback, coverage, height, parking and compliance figure the app shows. It is validated by 13 automated
tests in `src/lib/engine.test.cjs`:

```bash
node --test src/lib/engine.test.cjs
```

`src/lib/engine.cjs` is a byte-identical CommonJS copy used only so the Node test runner can `require()` it
directly (the app itself imports the ESM-side-effect version, `engine.core.js`, through the typed bridge in
`src/lib/engine.ts`). If you ever change the engine's logic, change `engine.core.js` and re-sync
`engine.cjs`, then re-run the test suite — don't let a fork of the logic drift.

**Why the engine is deterministic, not LLM-driven:** every planning-regulation number is looked up or
computed by explicit, tested code — never generated by a language model. The one place free text is accepted
(`Engine.parseCommand`, wired into the "Describe a change" box) is a fixed-grammar parser: it can only select
parameters the engine already knows how to compute, and can never invent a regulation value.

## Project structure

```
src/
  lib/
    engine.core.js / engine.cjs / engine.test.cjs   — the validated regulation engine (see above)
    engine.ts                                        — typed ESM bridge the app imports
    motion.ts                                         — shared framer-motion easing curve
  state/
    assessment.ts     — zustand store: active parcel, program, scenario, viewer mode
    consult.tsx        — global "free consultancy" modal context
  three/
    Massing3D.tsx       — react-three-fiber animated massing (floors rise/retarget on scenario change)
  components/           — shared UI: MetricCard, ScenarioTabs, ComplianceFlags, ComparisonTable,
                           CommandBox, InputPanel, SitePlan2D, ConsultModal, Logo, layouts
  pages/                 — marketing site: Home, Product, Pricing, Methodology
  pages/platform/        — the tool itself: Overview, Assessment, Investor, Reports
```

Routing is React Router (`HashRouter`, so the built app works from a plain static file host with no
server-side rewrite rules). State is a small zustand store shared across the platform routes so switching
between Assessment / Investor / Reports keeps the same active parcel.

## What's real vs. estimated vs. roadmap

The in-app Methodology page (`/methodology`) is the authoritative statement of this, and every metric card in
the tool carries its own FACT / ASSUMPTION / ESTIMATE / INTERPRETED tag plus a citation. In short: the
regulation-to-capacity engine and scenario studio are validated and tested; the investor feasibility screen is
real but runs on cost/price assumptions you supply; GIS parcel import, digitised area-specific zoning beyond
the general UDA regulation set, and full financial feasibility modelling are roadmap items, presented as such
rather than mocked to look finished.

## Extending to a new pilot zone

Add or edit the regulation tables at the top of `engine.core.js` (each entry carries its citation and
confidence level already) — the calculation logic, UI and test suite don't need to change. Re-run
`node --test src/lib/engine.test.cjs` before shipping any change to the tables.
